## MCP Server Configuration Guide

This comprehensive guide explains how to add MCP servers by defining their configuration in JSON format. Each MCP server entry is stored in the database and supports different transport types: stdio, SSE, and StreamableHTTP.

## MCP Configuration Overview

MCP (Model Context Protocol) configuration allows you to define how Keinsaas Navigator connects to and interacts with external tools and services. The configuration system supports multiple transport types and provides flexible options for different use cases.

## Transport Types

### stdio Transport

<AccordionGroup>
  <Accordion icon="terminal" title="What is stdio?">
    **Standard input/output transport**:
    
    - Direct process communication
    - Local server execution
    - High performance
    - Simple setup
    
    **Best for**: Local tools, development, simple integrations
  </Accordion>
  <Accordion icon="cog" title="Configuration Example">
    **stdio configuration**:
    ```json
    {
      "name": "local-file-server",
      "description": "Local file management server",
      "transport": "stdio",
      "command": "node",
      "args": ["/path/to/file-server.js"],
      "env": {
        "NODE_ENV": "production"
      }
    }
    ```
  </Accordion>
</AccordionGroup>

### SSE (Server-Sent Events) Transport

<AccordionGroup>
  <Accordion icon="broadcast" title="What is SSE?">
    **Server-Sent Events transport**:
    
    - Real-time communication
    - Web-based servers
    - Event streaming
    - HTTP-based
    
    **Best for**: Web services, real-time updates, cloud-based tools
  </Accordion>
  <Accordion icon="cog" title="Configuration Example">
    **SSE configuration**:
    ```json
    {
      "name": "web-analytics-server",
      "description": "Web analytics and reporting server",
      "transport": "sse",
      "url": "https://api.example.com/mcp/sse",
      "headers": {
        "Authorization": "Bearer your-token-here",
        "Content-Type": "application/json"
      }
    }
    ```
  </Accordion>
</AccordionGroup>

### StreamableHTTP Transport

<AccordionGroup>
  <Accordion icon="globe" title="What is StreamableHTTP?">
    **Streamable HTTP transport**:
    
    - HTTP-based communication
    - Streaming support
    - RESTful integration
    - Cloud-native
    
    **Best for**: REST APIs, microservices, cloud integrations
  </Accordion>
  <Accordion icon="cog" title="Configuration Example">
    **StreamableHTTP configuration**:
    ```json
    {
      "name": "database-server",
      "description": "Database access and management server",
      "transport": "streamablehttp",
      "url": "https://db.example.com/mcp",
      "method": "POST",
      "headers": {
        "Authorization": "Bearer your-db-token",
        "Content-Type": "application/json"
      },
      "timeout": 30000
    }
    ```
  </Accordion>
</AccordionGroup>

## Configuration Structure

### Basic Configuration Schema

```json
{
  "name": "server-name",
  "description": "Human-readable description",
  "transport": "stdio|sse|streamablehttp",
  "enabled": true,
  "timeout": 30000,
  "retry": {
    "attempts": 3,
    "delay": 1000
  },
  "auth": {
    "type": "none|bearer|basic|apikey",
    "credentials": {}
  },
  "tools": [],
  "resources": []
}
```

### Required Fields

<AccordionGroup>
  <Accordion icon="tag" title="name">
    **Server identifier**:
    
    - Unique name for the server
    - Used for identification and management
    - Must be alphanumeric with hyphens
    - Example: "my-database-server"
  </Accordion>
  <Accordion icon="text" title="description">
    **Human-readable description**:
    
    - Brief description of the server's purpose
    - Used in UI and documentation
    - Should be clear and concise
    - Example: "PostgreSQL database access server"
  </Accordion>
  <Accordion icon="plug" title="transport">
    **Transport type**:
    
    - Must be one of: stdio, sse, streamablehttp
    - Determines how the server is accessed
    - Affects configuration options
    - Example: "stdio"
  </Accordion>
</AccordionGroup>

### Optional Fields

<AccordionGroup>
  <Accordion icon="toggle" title="enabled">
    **Server status**:
    
    - Boolean value (true/false)
    - Controls whether server is active
    - Default: true
    - Can be changed without restart
  </Accordion>
  <Accordion icon="clock" title="timeout">
    **Connection timeout**:
    
    - Timeout in milliseconds
    - Default: 30000 (30 seconds)
    - Used for connection establishment
    - Should be appropriate for server type
  </Accordion>
  <Accordion icon="repeat" title="retry">
    **Retry configuration**:
    
    - Number of retry attempts
    - Delay between retries
    - Exponential backoff support
    - Helps with temporary failures
  </Accordion>
</AccordionGroup>

## Authentication Configuration

### No Authentication

```json
{
  "auth": {
    "type": "none"
  }
}
```

### Bearer Token Authentication

```json
{
  "auth": {
    "type": "bearer",
    "credentials": {
      "token": "your-bearer-token-here"
    }
  }
}
```

### Basic Authentication

```json
{
  "auth": {
    "type": "basic",
    "credentials": {
      "username": "your-username",
      "password": "your-password"
    }
  }
}
```

### API Key Authentication

```json
{
  "auth": {
    "type": "apikey",
    "credentials": {
      "key": "your-api-key",
      "header": "X-API-Key"
    }
  }
}
```

## Tool Configuration

### Defining Tools

<AccordionGroup>
  <Accordion icon="wrench" title="Tool Structure">
    **Basic tool configuration**:
    ```json
    {
      "tools": [
        {
          "name": "tool-name",
          "description": "Tool description",
    ```

  <Accordion icon="cog" title="Input Schema">

    - Defines required parameters

</AccordionGroup>

## Configuration Management

### Adding New Servers

<Steps>
  <Step title="Prepare Configuration">
    Create JSON configuration for your MCP server
  </Step>
  <Step title="Validate Configuration">
    Check that all required fields are present and valid
  </Step>
  <Step title="Add to Database">
    Insert configuration into the MCP servers table
  </Step>
  <Step title="Test Connection">
    Verify that the server can be reached and responds
  </Step>
  <Step title="Enable Tools">
    Activate the tools you want to use
  </Step>
  <Step title="Test Tools">
    Test individual tools to ensure they work correctly
  </Step>
</Steps>

### Updating Existing Servers

<AccordionGroup>
  <Accordion icon="edit" title="Configuration Updates">
    **Update server configuration**:
    
    - Modify existing configuration
    - Update authentication credentials
    - Change transport settings
    - Add or remove tools
  </Accordion>
  <Accordion icon="sync" title="Hot Reloading">
    **Apply changes without restart**:
    
    - Configuration changes take effect immediately
    - No need to restart Keinsaas Navigator
    - Tools become available instantly
    - Seamless user experience
  </Accordion>
</AccordionGroup>

### Removing Servers

<AccordionGroup>
  <Accordion icon="trash" title="Disable vs. Remove">
    **Two options for server management**:
    
    - **Disable**: Keep configuration but stop using server
    - **Remove**: Completely delete server configuration
  </Accordion>
  <Accordion icon="warning" title="Dependencies">
    **Check for dependencies**:
    
    - Ensure no workflows depend on the server
    - Check for active tool usage
    - Backup configuration before removal
    - Notify users of changes
  </Accordion>
</AccordionGroup>

## Common Configuration Examples

### Database Server

```json
{
  "name": "postgresql-server",
  "description": "PostgreSQL database access server",
  "transport": "stdio",
  "command": "node",
  "args": ["/path/to/postgres-mcp-server.js"],
  "env": {
    "DATABASE_URL": "postgresql://user:pass@localhost:5432/dbname"
  },
  "timeout": 30000,
  "retry": {
    "attempts": 3,
    "delay": 1000
  },
  "tools": [
    {
      "name": "query-database",
      "description": "Execute SQL queries on the database",
      "inputSchema": {
        "type": "object",
        "properties": {
          "query": {
            "type": "string",
            "description": "SQL query to execute"
          }
        },
        "required": ["query"]
      }
    }
  ]
}
```

### API Integration Server

```json
{
  "name": "weather-api-server",
  "description": "Weather data API integration server",
  "transport": "streamablehttp",
  "url": "https://api.weather.com/mcp",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer your-weather-api-key",
    "Content-Type": "application/json"
  },
  "timeout": 10000,
  "auth": {
    "type": "bearer",
    "credentials": {
      "token": "your-weather-api-key"
    }
  },
  "tools": [
    {
      "name": "get-weather",
      "description": "Get current weather for a location",
      "inputSchema": {
        "type": "object",
        "properties": {
          "location": {
            "type": "string",
            "description": "City name or coordinates"
          }
        },
        "required": ["location"]
      }
    }
  ]
}
```

### File System Server

```json
{
  "name": "file-system-server",
  "description": "Local file system access server",
  "transport": "stdio",
  "command": "python",
  "args": ["/path/to/filesystem-mcp-server.py"],
  "timeout": 15000,
  "tools": [
    {
      "name": "read-file",
      "description": "Read contents of a file",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": {
            "type": "string",
            "description": "Path to the file to read"
          }
        },
        "required": ["path"]
      }
    },
    {
      "name": "write-file",
      "description": "Write content to a file",
      "inputSchema": {
        "type": "object",
        "properties": {
          "path": {
            "type": "string",
            "description": "Path where to write the file"
          },
          "content": {
            "type": "string",
            "description": "Content to write to the file"
          }
        },
        "required": ["path", "content"]
      }
    }
  ]
}
```

### Performance Optimization

- **Connection Pooling**: Use connection pooling for database servers
- **Timeout Settings**: Set appropriate timeouts for different server types
- **Retry Logic**: Implement smart retry logic for transient failures
- **Monitoring**: Monitor server performance and health
- **Caching**: Use caching where appropriate to reduce load

## Troubleshooting

### Common Issues

<AccordionGroup>
  <Accordion icon="exclamation-triangle" title="Connection Failures">
    **If servers won't connect**:
    
    - Check network connectivity
    - Verify server URLs and ports
    - Confirm authentication credentials
    - Check firewall settings
  </Accordion>
  <Accordion icon="key" title="Authentication Errors">
    **If authentication fails**:
    
    - Verify API keys and tokens
    - Check credential expiration
    - Confirm permission levels
    - Test with different credentials
  </Accordion>
  <Accordion icon="clock" title="Timeout Issues">
    **If requests timeout**:
    
    - Increase timeout values
    - Check server performance
    - Optimize query complexity
    - Review network latency
  </Accordion>
</AccordionGroup>
